MELBA 2021

A website of 19 interactive jars for the 4th Melba Sofia Design Festival, 11–21 November 2021.

Concept

The festival's visual identity grew out of a classic Bulgarian tradition: jars of compotes and pickles, preserving the best of a season. The festival did the same with design, sealing every part of the 2021 programme inside its own container.

My job was to make those containers interactive. Every section of the site lives inside its own jar—the menu, the line-up, the speakers, and the about page. Each one holds illustrated produce (peaches, carrots, broccoli, pinecones), soft wobbling jelly blobs, and the section name broken into floating typographic pieces. When a user passes their cursor over the layout, the physics engine takes over—everything drifts, bumps into its neighbors, and slowly settles back into place.

The Ancestral Method

This was 2021, when the only way to tune a jelly blob was to change a decimal point, hard-reload the tab, and watch it either set into stone or melt into digital soup. No AI agents, no code run on vibes, just YouTube tutorials and getting lost in the docs.

Under the Lid

  1. Invisible walls

    Each jar is its own Matter.js world, sealed by six invisible static walls. The jar you see is the illustrator's drawing, layered over the canvas, with the walls hand-placed to match its outline. The physics and the drawing never touch; they just agree on where the glass is.

  2. Gravity: weightless, not falling

    Gravity is off, so everything floats as if suspended in syrup. Every object is five times Matter's default weight and has zero bounce, so collisions land softly rather than springily.

  3. Shapes: collider and skin

    Matter.js can only collide convex polygons; even its circles are polygons. The festival's illustrations are crescents, fans and spiky leaves. So every object has two layers: a collider the engine simulates, and a skin visitors see.

    The collider is a hidden SVG in the page: a simplified, straight-edged outline of the illustration. At load, Matter reads it into points. It samples curves pixel by pixel but straight edges only at their corners, so a straight-edged outline keeps the shape light. A peach becomes 11 points instead of hundreds.

    Concave outlines are the catch. The engine can't collide them directly, and without help Matter quietly falls back to the outline's convex hull, so a leaf would collide as a solid lump, bumping into the air between its blades. poly-decomp solves it by cutting each concave outline into convex pieces, which Matter welds into one compound body. Reading the SVGs also needed the pathseg polyfill, because Chrome had removed the browser API Matter uses for it.

    The skin comes in two kinds. Illustrated produce gets a PNG sprite drawn over its body, each with its own scale factor so the drawing lines up with the collider. One peach outline, reused at four sizes and rotations, gives the Symposium jar six peaches. Flat shapes like leaves skip the sprite: the collider polygon is the drawing, filled with a single colour.

    Skins: what visitors saw. Colliders: what the physics engine simulates. The outlines are the real ones from the live site; the shaded pieces are the leaf's convex parts, and the dashed shapes are the invisible walls hiding behind the drawn glass. Hover or drag across the jar to nudge the contents.

  4. How the jelly blobs work

    The soft blobs aren't rigid bodies at all. Each one is a ring of invisible physics dots (between 16 and 44, depending on the blob), and every dot has three connections:

    • a rigid link to its neighbour, so the ring keeps its length
    • a loose spring to the dot two places along, so the ring can't fold in on itself
    • a weak tether to its starting point, so the blob always drifts home

    A second canvas, drawn with Paper.js, runs a smooth curve through the dots every frame, so a handful of points reads as one continuous, wobbling shape. When a peach bumps into the ring, the dots give way, then the tethers pull them back.

    Tether pulls each dot back home. Shape spring stops the ring folding in on itself. Original is the Review jar's tuning: 16 dots, tether 0.009, shape spring 0.04. Poke the blob, or shake the jar.

  5. Every speaker, preserved

    Each of the six symposium speakers got their own jar, with their name floating inside as physics pieces that link to their page. In four of them, the speaker's portrait is sealed inside the jelly: the photo is clipped to the blob's shape, so when something bumps into it, the face wobbles along with it. Each speaker's page then repeats the trick at full scale, with one giant jar framing the whole profile.

  6. A nudge, not a click

    The interaction is hover only. When the cursor passes over an object, it gets a push in a random direction, scaled by its own mass, so a heavy peach and a light dot react comparably. Each jar has its own tuning, gentler in some and livelier in others. The name pieces are links, so the menu is still a menu, just one that moves.

  7. Nineteen worlds, one idle state

    Running this many physics simulations is a real cost, so each jar puts itself to sleep: once every object has come to rest, it stops drawing entirely, and the next hover wakes it. The layout is also scaled with CSS at different screen sizes, so every jar corrects the mouse position for that scale and the hover stays precise.

  8. One class per jar, one class per shape

    The code is object-oriented, built from ES6 modules and classes. Each of the 19 jars is its own class that owns its engine, renderer, walls, contents and interaction. A shared particles module defines seven shape classes (Rectangle, Circle, Boundary, Polygon, Trapezoid, Svg and SvgTexture), each packaging the physics settings every object needs: weight, zero bounce, and its sprite skin. Filling a jar is mostly a list of new SvgTexture('peach', …) calls. A shared config holds each illustration's sprite scale, so a peach looks the same in every jar it appears in.

Behind the jars

19 jars · 824 physics bodies · 1,130 constraints

Six jars on the homepage, six on the symposium page, one framing every speaker's page, and one on About. Together they hold 326 floating objects and 15 jelly blobs.

If I rebuilt it today, I'd push the object-oriented approach one step further: a shared base jar class for the engine, hover and sleep logic that all 19 currently repeat.
